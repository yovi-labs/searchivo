# Developer experience and repository presentation

The owner requested a professional playground, documentation and repository presentation. Improve the existing static site instead of adding a UI framework. Keep the playground lazy-loaded and use the real packages for behavior.

Four deterministic presets restore known defaults before showing exact matching, typo recovery, BM25 explanations or worker ranking. Controls use native disclosure groups; the inspector shows query tokens, source fixtures and copyable local engine configuration. The snippet explicitly excludes filters and worker orchestration. No local-storage persistence or shareable URL contract is introduced.

The Markdown guide remains the documentation source. The website adds searchable topic sections and task-oriented learning paths. Repository documentation provides the same entry points without requiring a running website. README screenshots come from the actual built application and are stored under docs/assets.

Contribution, security, issue and pull-request guidance documents the current private/pre-1.0 state without inventing a support SLA or security contact. No publishing, deployment or branch-policy changes are included. Earlier private candidates remain tied to their original revision.
